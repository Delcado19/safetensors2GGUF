## [Unreleased]

### Add
- **Text-encoder conversion now supports the full GGUF K-quant palette and FP8/NVFP4 safetensors output**, not just F32/F16/BF16/Q8_0. `text_encoder_convert.py` gains `TEXT_ENCODER_FORMAT_CHOICES` (replaces the GUI-facing `TEXT_ENCODER_OUTTYPES` dropdown) covering three backends:
  - `Q6_K`/`Q5_K_M`/`Q4_K_M`/`Q4_K_S`/`Q3_K_M`/`Q2_K`: `convert_text_encoder_kquant()` runs the existing F16 GGUF conversion, then quantizes with `run_quantize()` (reused from `quantize.py`) using a **new, separate** plain llama-quantize binary — `ensure_plain_llama_quantize()` builds it once via `cmake` from the already-auto-cloned llama.cpp checkout (cached under `.llama.cpp/build-quantize/`). Deliberately distinct from the City96-patched binary used for diffusion-model GGUFs, which `docs/building-llama-quantize.md` documents as unsafe for LLM/text GGUFs.
  - `FP8`/`FP8_MIXED`/`NVFP4`/`NVFP4_MIXED`: `convert_text_encoder_to_safetensors()` reuses `convert_safetensors.convert_to_safetensors()` (which gained an optional `model_arch` parameter) with a bare `ModelTemplate()` instance instead of the diffusion-model architecture detection — text encoders aren't in `arch_list` and don't need to be: ComfyUI's text-encoder loaders build models from fixed config presets rather than inferring hyperparameters from checkpoint tensor shapes, so the generic 1D-skip/16-multiple-fallback safety rules are sufficient (no per-architecture `keys_shape_critical` audit needed, unlike the diffusion-model NVFP4 fix above). No HuggingFace download or llama.cpp involved for this path at all.
  - `convert_text_encoder_any()` is the new single dispatcher `gui.py`'s `run_te_convert()` calls, branching on the selected format.

### Fix
- **Re-quantizing an already-quantized source checkpoint silently corrupted it**: some published checkpoints (e.g. ComfyUI-native `int8_tensorwise`+ConvRot releases) are already partially quantized, storing raw integer weights alongside their own pre-existing `.weight_scale`/`.comfy_quant` sidecar tensors right in the state dict. This tool had no concept of that — it iterated every tensor and re-quantized each one as an ordinary weight, including the pre-existing scale/metadata sidecars themselves (a `[rows,1]` float32 `.weight_scale` tensor looks just like a small 2D weight matrix), producing corrupted output with mis-named `_quantization_metadata` layer keys (an extra `.weight_scale` suffix, since `layer_key()` only strips a trailing `.weight`). Found by tracing a user's FP8_MIXED noise-image report: 170 of 378 layers in the output had corrupted metadata keys, all tracing back to a source checkpoint (`juggernautZ_v10ByRundiffusion.safetensors`) that turned out to already be `int8_tensorwise`-quantized — confirmed by its own embedded `_quantization_metadata`. Fixed by adding `_check_not_already_quantized()` (`convert_safetensors.py`), which raises before conversion starts if any `.comfy_quant` sidecar key is present anywhere in the state dict, or any `.weight` tensor is stored as int8/uint8 (bare float8 weights are still allowed through — an existing, deliberately-supported case, coerced to float16). Verified against both the corrupted source (raises) and a genuinely unquantized sibling file in the same directory (does not raise). See `docs/issues_analysis.md` #12.
- **Every NVFP4 safetensors conversion decoded every weight at exactly half its intended magnitude**: `safetensors_quant_nvfp4.py`'s `_KVALUES` E2M1 decode table used `gguf.quants.NVFP4.kvalues`'s **doubled** magnitudes (`0,1,2,3,4,6,8,12,…`), per its own docstring claim of matching that table. But gguf's table is doubled specifically to compensate for a *different*, custom per-block scale encoding gguf's NVFP4 uses internally (`ue4m3_to_fp32`, which bakes in a `*0.5` decode factor) — this tool never used that encoding, it writes plain `torch.float8_e4m3fn` block scales (what ComfyUI's `comfy_kitchen` actually expects), so pairing that with gguf's doubled table silently halved every decoded weight. Reported by a user as pure-noise/garbage NVFP4_MIXED output persisting even after the shape-crash and swizzle-layout fixes below. This tool's own round-trip tests never caught it — quantizing and dequantizing with the same (wrong) table cancels the error out, only surfacing against ComfyUI's real, independent decoder. Found by comparing `quantize_nvfp4()` output directly against `comfy_kitchen.tensor.nvfp4.TensorCoreNVFP4Layout`'s own quantize/dequantize on a live ComfyUI install: a block filled with the exact table value `6.0` decoded back to `3.0`, showing the 2x error directly. Fixed by replacing `_KVALUES` with the standard undoubled OCP E2M1 magnitudes (`0,0.5,1,1.5,2,3,4,6,…`) — the existing `/6.0` scale divisors already assumed this range. Verified against `comfy_kitchen`'s own reference on a random tensor: mean reconstruction error 0.2857 (ours) vs. 0.2856 (ComfyUI's own). Added `test_kvalues_are_standard_undoubled_e2m1_magnitudes` and `test_block_of_exact_table_values_round_trips_exactly`.
- **Every NVFP4 safetensors conversion produced a `.weight_scale` tensor in the wrong on-disk layout for every 2D (Linear) weight** — not just the one layer a user hit a crash on: `safetensors_quant_nvfp4.py` wrote each layer's `.weight_scale` as a plain, unpadded `(rows, k_blocks)` tensor, but ComfyUI's `comfy_kitchen` CUDA backend (`scaled_mm_nvfp4`) requires block scales padded to `(roundup(rows,128), roundup(k_blocks,4))` **and** rearranged into a 128x4 block-interleaved layout — the same convention vLLM's `swizzle_blockscale()` and TensorRT-Model-Optimizer NVFP4 checkpoints use. Concretely, this means two distinct symptoms depending on the layer's shape, both present in every prior NVFP4/NVFP4_MIXED conversion:
  - Layers whose output width isn't already a multiple of 128 (or block count a multiple of 4) fail the kernel's shape assertion outright — reported by a user as a crash (`AssertionError: Invalid B scale shape`) on Lumina2/Z-Image's `final_layer.linear.weight`.
  - Layers whose dimensions already happen to be multiples of 128/4 (most transformer block weights — hidden_size, mlp_dim, …) pass the shape check, but the scale values are read in the wrong order by the kernel, since a plain zero-padded tensor and the required interleaved layout have the same shape but different element order. This loads silently wrong (not crashing) weights.

  Root-caused by reading `comfy_kitchen`'s CUDA backend source directly (`roundup_n`/`roundup_sk` formula) and cross-verified against vLLM's open-source `nvfp4_utils.py` implementation of the identical layout. Fixed by adding `_swizzle_block_scale()`/`_unswizzle_block_scale()` (2D weights only — the case that reaches this kernel path) to `safetensors_quant_nvfp4.py`, applied unconditionally in `quantize_nvfp4()`. Existing NVFP4 tests updated for the new padded/swizzled `weight_scale` shape; added `test_scale_swizzled_shape_matches_comfy_kitchen_kernel_formula` and `test_swizzle_matches_vllm_reference_implementation` (a literal transcription of vLLM's function, since a self-inverting swizzle/unswizzle round-trip test alone can't detect a layout that's internally consistent but wrong relative to the real kernel).
- **`ensure_plain_llama_quantize()` couldn't actually use an auto-detected Visual Studio on Windows**: `_locate_msvc_build_env()` (added alongside the K-quant feature above, for the common case where VS is installed but its tools were never added to the user's PATH) had two bugs, both found and fixed via a real end-to-end build on a Windows machine with VS installed but nothing on PATH:
  - The `cmd /c "call \"<vcvarsall>\" x64 && set"` invocation used to capture vcvarsall's environment variables failed outright — `subprocess`'s Windows argument-quoting (`list2cmdline`) re-quotes an argument that itself contains both spaces and quotes (the vcvarsall path), mangling the nested quotes so cmd.exe couldn't find the batch file at all (silent `FileNotFoundError`, caught and treated as "no VS found"). Fixed by writing the `call`+`set` sequence to a temp `.bat` file and running that instead — sidesteps the nested-quoting problem entirely.
  - Even with the environment captured correctly, passing it as `subprocess.run(["cmake", ...], env=build_env)` still raised `FileNotFoundError`: on Windows, `env=` only sets the **child** process's environment block — the executable itself is still resolved against the **calling** process's own `PATH`, not `build_env`'s. Fixed by resolving `cmake`'s absolute path via `shutil.which("cmake", path=build_env["PATH"])` before invoking it, instead of relying on Windows to search `build_env["PATH"]` (it doesn't). Added `test_resolves_cmake_absolute_path_from_located_msvc_env` regression test.
- **FP8/NVFP4 safetensors output was silently broken in ComfyUI**: `safetensors_quant_fp8.py`/`safetensors_quant_nvfp4.py` named the per-layer scale sidecar tensor `<full_tensor_name>.weight_scale` (e.g. `x_embedder.weight.weight_scale`), but ComfyUI's quantized-op loader (`comfy/ops.py _load_quantized_weight_body`, confirmed by reading a live ComfyUI 0.29.2 install) looks up `<module_prefix>weight_scale` — a **sibling** of `<module_prefix>weight`, not nested under it (e.g. `x_embedder.weight_scale`). The mismatch meant every `.weight_scale`/`.weight_scale_2`/`.comfy_quant` tensor we wrote was reported by ComfyUI as an "unexpected key" and silently discarded: FP8 checkpoints loaded the raw unscaled float8 bytes as weights (visible as solid-noise output images), and NVFP4 additionally crashed on some checkpoints (see below). Root-caused via a user bug report showing garbage Z-Image output from a `FP8_MIXED` conversion and a `RuntimeError` shape mismatch from `NVFP4_MIXED`. Fixed by adding `safetensors_quant.layer_key()` (strips a trailing `.weight` to get the module prefix ComfyUI expects) and using it consistently for scale-tensor naming and the `_quantization_metadata` "layers" dict key in `convert_safetensors.py`. All existing FP8/NVFP4 tests updated to the corrected naming; added `test_quantization_metadata_layer_key_has_no_weight_suffix` regression test.
- **NVFP4 could corrupt ComfyUI's architecture-hyperparameter detection**: independent of the naming bug above, ComfyUI's `model_detection.py` infers hyperparameters directly from specific tensors' raw on-disk shapes before any dequantization — a pattern used across ComfyUI's supported architectures, not just Lumina2 (e.g. Flux infers `in_channels` from `img_in.weight.shape[1]`, Lumina2 infers `cap_feat_dim` from `cap_embedder.1.weight.shape[1]`). NVFP4 halves a packed tensor's on-disk last dimension (2 values/byte), corrupting that inference and crashing model load — this is a gap in this tool's non-mixed NVFP4 path (which packed those tensors indiscriminately), not a ComfyUI bug: published NVFP4 checkpoints conventionally leave small embedding/patchify layers unquantized anyway. Added `ModelTemplate.keys_shape_critical` (`models/architectures.py`) to exclude flagged tensors from NVFP4 packing unconditionally (not gated by `*_MIXED`, since this is shape-safety, not precision). Audited every architecture against a live ComfyUI install and populated it for `ModelFlux`/`ModelQwenImage` (`img_in.weight`), `ModelSD3` (`context_embedder.weight`), `ModelAura` (`cond_seq_linear.weight`), `ModelLumina2` (`cap_embedder.1.weight`), `CosmosPredict2` (`x_embedder.proj.1.weight`), `ModelHyVid` (`txt_in.input_embedder.weight`), `ModelWan` (`head.modulation`), and `ModelLTXV` (`transformer_blocks.0.attn2.to_k.weight`) — `ModelHiDream` was audited and confirmed to need no fix (its `unet_config` is hardcoded constants, no shape reads). `ModelSDXL`/`ModelSD1` remain unaudited (ComfyUI's `context_dim` detection there scans block indices dynamically rather than reading one fixed tensor name) — see `docs/issues_analysis.md` #9 for the full per-architecture table.
- `gui.py`: The **Convert → Safetensors** tab's output-path Browse button opened a file-*open* dialog (`_browse(_MODEL_TYPES)`, meant for picking a source model) instead of a directory picker. Added `browse_and_set_dst_st()` (mirrors the GGUF tab's `browse_and_set_dst()`) and `_resolve_dst_st()`, which defers the output format into the filename via a `{ftype}` placeholder so the name reflects whatever format is selected at convert time, not whatever was selected when Browse was clicked.

### Fix
- Final integration review fix wave for the Safetensors-output / Text-Encoder feature branch (5 cross-task findings):
  - `safetensors_quant.py` (`quantize_tensor_st`): NVFP4 quantization of a tensor whose last dimension isn't a multiple of 16 (e.g. a 3x3 conv kernel, last dim 3 — routine in SDXL/SD1.5 UNets and some DiT patch-embed layers) now catches `quantize_nvfp4`'s `ValueError` and falls back to a plain F16 write for that one tensor, instead of crashing the whole conversion after many tensors were already processed.
  - `safetensors_quant.py` (`quantize_tensor_st`): 1D tensors (biases, norm weights) are now unconditionally excluded from FP8-scaled/NVFP4-block-scaled quantization, not just in `*_MIXED` mode. Previously non-mixed `FP8`/`NVFP4` scale-quantized 1D tensors and emitted a `<name>.weight_scale` sibling that no consumer reads (ComfyUI's scaled-quant loader only applies `.weight_scale` to a layer's `.weight`), so biases loaded back unscaled and wrong by up to ~448x. Mirrors `convert.py`'s `_quant_type_for`, which already keeps 1D tensors at F32 unconditionally.
  - `gui.py`: The **Convert → Safetensors** tab's format dropdown now defaults to `FP8_MIXED` instead of `FP8`, since mixed mode keeps hiprec tensors at F32 for extra safety margin.
  - `convert_safetensors.py`: Stopped materializing the entire state-dict into a `list()` before iterating — this defeated `load_state_dict()`'s lazy `_LazyStateDict` streaming (added in `72a49dc` specifically to bound peak RAM to ~1 tensor for >RAM checkpoints) and reintroduced the OOM/paging crash that commit fixed. Now uses `len(state_dict)` and iterates `state_dict.items()` directly, both of which `_LazyStateDict` supports without loading tensor data.
  - `gui.py` (`run_te_convert`): Cancelling the **Convert Text Encoder → GGUF** tab now renders "Cancelled" instead of a red "Error: cancelled" — added the same `RuntimeError("cancelled")` special-case already present in `run_st_convert`.
  - `README.md`: Removed the "(or `convert_safetensors.py` CLI)" / "(or `text_encoder_convert.py` CLI)" mentions — neither module has an `argparse`/`__main__` entry point; both are GUI-only features.
- `safetensors_quant_nvfp4.py`: Guard zero/near-zero blocks against NaN division. Original code relied on implicit `argmin(NaN)→0, _KVALUES[0]==0` coincidence; replaced with explicit `torch.where` guard detecting post-cast zero block scales and deliberately zeroing normalized values for affected blocks. Prevents silent correctness bugs if PyTorch's NaN-handling behavior changes across versions/backends. Added `test_zero_block_no_nan_and_reconstructs_to_zero` to cover all-zero and near-zero tensors.

### Change
- `convert.py`: Stream safetensors tensors one at a time instead of loading the full state-dict into RAM. Replaces `safetensors.torch.load_file()` with a new `_LazyStateDict` wrapper around `safe_open()` that materializes tensors on demand via `get_tensor()`. Required to convert checkpoints larger than physical RAM (e.g. the 19 GiB FP8 `Qwen-Edit-abliterated-4step-v1.safetensors` on a 16 GiB system, which previously crashed mid-conversion with `KERNEL_DATA_INPAGE_ERROR` and segfaults caused by excessive Windows paging). Source dtype detection now reads dtypes from the safetensors header instead of iterating `.values()`, so dominant-dtype detection also stays out of RAM. `.ckpt` / `.pt` / `.bin` / `.pth` sources keep the existing eager path because `torch.load` has no streaming API.
- `convert.py`: `strip_prefix` refactored to share its prefix rules with the lazy path via a new `_build_key_map(keys)` helper. Public API and behaviour for eager dicts unchanged.
- `convert.py`: `GGUFWriter` now runs with `use_temp_file=True` so converted tensors spill to a `SpooledTemporaryFile` (256 MiB RAM buffer, remainder on disk in `%TEMP%`) instead of accumulating every F16/BF16 tensor in `self.tensors`. Without this, lazy-streaming on the read side only deferred the OOM: the Qwen-Edit 19 GiB FP8 conversion progressed to tensor 1384/1933 (71%) before crashing because the writer had buffered roughly 27 GiB of F16-equivalent tensor data in RAM. Pairs with `_LazyStateDict` to keep peak RAM bounded end-to-end.

### Add
- `text_encoder_convert.py`: Bare-bones text-encoder (LLM/T5) safetensors → GGUF conversion support. Exports `find_convert_script()` and `find_embedded_python()` discovery functions that search ComfyUI-Easy-Install roots for `python_embeded/Lib/site-packages/llama_cpp/bin/convert_hf_to_gguf.py` and `python_embeded/python.exe`; reuses `quantize._easy_install_roots()` binary-discovery pattern. Defines `TEXT_ENCODER_OUTTYPES` (F32/F16/BF16/Q8_0) dropdown choices for the planned GUI. Foundation for Tasks 8–9 (config/tokenizer download, subprocess runner, and GUI integration). Bare single-file safetensors cannot be converted by `convert_hf_to_gguf.py` directly because it requires config.json + tokenizer files; planned workflow downloads these from HuggingFace + assembles a temp directory with renamed weights before invoking the embedded Python interpreter's script.
- `tests/test_text_encoder_convert.py`: Coverage for discovery functions (returns None when not found, finds scripts/pythons under Easy-Install roots), and `TEXT_ENCODER_OUTTYPES` structure (list of non-empty string tuples).
- `text_encoder_convert.py`: `fetch_base_config_files(repo_id, dest_dir, on_log=None)` — downloads a base model's `config.json` (mandatory) and best-effort tokenizer files (`tokenizer.json`, `tokenizer_config.json`, `tokenizer.model`, `special_tokens_map.json`) from HuggingFace Hub into `dest_dir`. Returns the list of filenames actually downloaded. Raises `RuntimeError` if `config.json` is missing (mandatory constraint); tokenizer files are optional and skipped individually if not found (since repos vary in which tokenizer variants they ship). Used in the text-encoder workflow to fetch supplemental config/tokenizer files when converting bare safetensors to GGUF.
- `tests/test_text_encoder_convert.py`: Coverage for `fetch_base_config_files` (downloads config + available tokenizers, best-effort missing-file handling, RuntimeError on missing config.json).
- `text_encoder_convert.py`: `convert_text_encoder(weights_path, base_repo_id, dst_path=None, outtype="f16", on_log=None, cancel_event=None)` — orchestration function that converts a bare single-file text-encoder checkpoint to GGUF. Assembles a temporary HF-style model directory with the user's weights (copied as `model.safetensors` to preserve the original) plus downloaded config/tokenizer files, then runs `convert_hf_to_gguf.py` via the ComfyUI-Easy-Install embedded Python interpreter. Streams subprocess output to `on_log`, respects `cancel_event` for graceful cancellation, and returns the output GGUF path. Raises `FileNotFoundError` if convert script or embedded python is not found; raises `RuntimeError` if the subprocess exits with non-zero code or is cancelled.
- `tests/test_text_encoder_convert.py`: Coverage for `convert_text_encoder` (raises FileNotFoundError when convert script not found, runs subprocess with expected command-line arguments).
- `pyproject.toml`: Add `huggingface_hub` dependency for base-model config/tokenizer download support in text-encoder conversion.
- `safetensors_quant.py`: Quantized Safetensors → Safetensors output backend with dtype registry (F16/F16-mixed variants) and per-tensor quantization. Reuses `convert._quant_type_for`'s high-precision-tensor rule so mixed-precision safetensors output exactly matches existing GGUF mixed-precision behavior. Foundation for Task 2–3 (FP8/NVFP4 variants) and Tasks 4–5 (convert_safetensors.py and GUI integration).
- `tests/test_safetensors_quant.py`: Coverage for safetensors dtype registry, high-precision-tensor detection, and F16/F16-mixed quantization
- `safetensors_quant_fp8.py`: ComfyUI-compatible scaled FP8 quantization for safetensors output (`float8_e4m3fn` with per-layer `weight_scale` metadata). Follows ComfyUI's scaled_fp8 convention (see `comfy/quant_ops.py` QUANT_ALGOS["fp8"] in city96/ComfyUI-GGUF).
- `tests/test_safetensors_quant_fp8.py`: Coverage for FP8 scaling, packing, dtype outputs, and round-trip reconstruction accuracy
- `safetensors_quant_nvfp4.py`: NVFP4 block-scaled 4-bit quantization for safetensors output (uint8-packed with per-16-element block scaling and global scale). Reuses `gguf.quants.NVFP4`'s E2M1 codebook table for bit-compatibility with ComfyUI's native NVFP4 loader (format reference: city96/ComfyUI-GGUF `comfy/quant_ops.py` QUANT_ALGOS["nvfp4"]).
- `tests/test_safetensors_quant_nvfp4.py`: Coverage for NVFP4 quantization (packing, scaling, dtype outputs, error cases, and round-trip reconstruction accuracy)

Placed before `ModelFlux` / `ModelSD3` in `arch_list` because Qwen-Image shares `transformer_blocks.0.attn.norm_added_k.weight` and `add_q_proj.weight` with those architectures, which would otherwise trigger their reference-format `keys_banned` guard and abort conversion with "Model architecture not allowed for conversion.
